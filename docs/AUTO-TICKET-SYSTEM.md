# 自动建单功能说明

## 📋 概述

系统监控代理在检测到设备异常时，会自动创建技术支持工单。**自动建单比人工建单更详细**，包含完整的诊断信息、环境快照、设备状态和建议操作。

---

## 🎯 触发场景

### 1. 手套接线错误（左右手接反）
- **优先级**: P2
- **触发条件**: 检测到的 SN 码在注册表中标记的左右手与实际接入端口不符
- **典型表现**: 左手网口（192.168.1.100）检测到右手手套的 SN

### 2. 设备状态异常（不可投入使用）
- **优先级**: P1（高优先级）
- **触发条件**: 设备 SN 在系统中标记为 damaged/transferred/shipped/repairing/waiting_repair/scrapped
- **典型表现**: 连接的设备在系统中显示为"损坏"或"维修中"

### 3. 设备串用（SN 绑定在其他机器）
- **优先级**: P2
- **触发条件**: 检测到的 SN 已绑定在其他机器上
- **典型表现**: we-100 检测到的手套 SN 在系统中绑定在 we-101

### 4. 设备未登记入库
- **优先级**: P3
- **触发条件**: 检测到的 SN 码未在 sn_registry 表中登记
- **典型表现**: 新设备或 SN 识别错误

### 5. 绑定设备未连接（可选）
- **优先级**: P3
- **触发条件**: 系统记录该机器绑定了某个 SN，但设备未连接
- **默认**: 不自动建单（需设置 `EDGE_AUTO_TICKET_EXTRA=bound_but_disconnected`）
- **原因**: 下班关机误报较多

### 6. 手套 SN 无法识别（可选）
- **优先级**: P3
- **触发条件**: 手套已连接但无法识别 SN 码
- **默认**: 不自动建单（需设置 `EDGE_AUTO_TICKET_EXTRA=glove_no_sn`）
- **原因**: 可能仅缺标定文件，不一定是故障

## 🔍 详细信息说明

### 诊断详情
- **观测到的 SN**: 边缘代理实际检测到的 SN 码
- **系统登记 SN**: sn_registry 表中记录的 SN
- **应该接入**: 根据注册表应该接入的网口
- **实际接入**: 实际检测到设备的网口
- **设备状态**: 设备在系统中的状态（available/in_use/damaged等）
- **绑定机器**: 设备当前绑定的机器编号
- **可能原因**: 自动分析的可能原因
- **建议操作**: 针对性的操作建议

### 设备状态快照
- **手套**: 左右手连接状态 + SN 码
- **灵巧手**: 左右手连接状态
- **机械臂**: 连接状态
- **Quest 头显**: 连接状态 + 电池电量

### 环境信息
- **主机名**: 工作站 hostname
- **IP 地址**: 工作站 IP
- **代理版本**: heartbeat-agent 版本号
- **最后心跳**: 最近一次心跳时间
- **CPU 核心数**: 处理器核心数
- **总内存**: 物理内存大小

### 告警上下文
- **首次检测**: 本次告警首次出现的时间
- **发生次数**: 相同告警的累计次数
- **相关告警**: 同一时间其他告警（帮助判断关联性）

## 🎛️ 配置选项

### 环境变量

```bash
# 关闭自动建单（默认开启）
EDGE_AUTO_TICKET=off

# 扩展自动建单范围（逗号分隔）
EDGE_AUTO_TICKET_EXTRA=bound_but_disconnected,glove_no_sn

# 自定义系统建单提交人（默认 sa-002）
EDGE_TICKET_SUBMITTER_ID=sa-002
```

### 默认建单的告警类型
- `hand_mismatch` - 手套接线错误
- `sn_unusable` - 设备状态异常
- `sn_bound_elsewhere` - 设备串用
- `unregistered_sn` - 设备未登记

### 可选建单的告警类型
- `bound_but_disconnected` - 绑定设备未连接（误报多）
- `glove_no_sn` - 手套 SN 无法识别（不一定是故障）

## 🛡️ 防刷屏机制

### 1. 去重检查
同一台机器如果已有 `pending` 或 `in_progress` 状态的工单（无论人工还是自动），不会重复建单。

### 2. 防抖机制
同一告警（code:hand:snCode）如果因"已有工单"跳过建单，会记录时间戳，10分钟内不再重试。

### 3. 告警恢复自动清理
当告警消失（下次心跳不再出现）时，自动清除建单标记，允许复发后重新建单。

### 4. 不自动关单
自动建单的工单不会自动完成，**必须运维人员手动确认维修结果后关单**。

## 📝 工单字段

自动建单包含以下额外字段（人工建单没有）：

```javascript
{
  autoCreated: true,              // 自动建单标记
  alertCode: "hand_mismatch",     // 告警代码
  source: "edge_agent",           // 来源
  diagnosticsData: { ... },       // 原始诊断数据
  deviceSnapshotData: { ... },    // 原始设备快照
  environmentData: { ... },       // 原始环境信息
  alertContextData: { ... }       // 原始告警上下文
}
```

这些原始数据可用于后续分析、统计和机器学习。

## 🎯 运维操作

### 查看自动建单
运维端"技术支持"页面会显示所有工单，自动建单有特殊标记：
- 提交人显示为：`系统监控（边缘代理）（系统自动）`
- 故障描述以 `【系统自动检测·边缘代理】` 开头

### 响应工单
自动建单和人工建单的响应流程完全相同：
1. 点击"响应"按钮
2. 系统记录响应人和响应时间
3. 机器状态变更为 `repairing`
4. 运维人员前往现场处理

### 完成工单
需要填写维修结果：
1. 点击"完成"按钮
2. 填写维修结果（必填）
3. 系统记录完成时间
4. 机器状态根据手套绑定情况自动更新

## 📈 统计分析

自动建单的数据可用于：
- 故障类型分析（哪种故障最常见）
- 响应时间分析（平均响应速度）
- 解决时间分析（平均维修时长）
- 设备健康度分析（哪些机器故障率高）
- 告警趋势分析（故障增加还是减少）

## 🔧 故障排查

### 问题1：没有自动建单

**检查**：
```bash
# 1. 检查是否关闭了自动建单
echo $EDGE_AUTO_TICKET

# 2. 检查告警类型是否启用
# 查看 edge.js 中的 DEFAULT_TICKET_CODES

# 3. 检查是否已有未完成工单
curl "http://10.5.51.216:8765/api/tech-support?machineNumber=we-100&status=pending"
```

### 问题2：自动建单太多

**解决**：
```bash
# 关闭可选的告警类型建单
# 移除 EDGE_AUTO_TICKET_EXTRA 环境变量

# 或完全关闭自动建单
export EDGE_AUTO_TICKET=off
```

### 问题3：告警恢复但工单未关闭

**正常行为**：自动建单不会自动关单，必须运维人员手动确认维修结果。

原因：避免误关单，确保每个故障都经过人工验证。

## ✅ 总结

自动建单功能的核心优势：

1. **更详细** - 包含完整的诊断信息、环境快照、设备状态
2. **更及时** - 30秒内检测并建单
3. **更准确** - 基于系统数据比对，减少人为错误
4. **更智能** - 自动分析可能原因和建议操作
5. **防刷屏** - 去重、防抖机制避免工单堆积
6. **可追溯** - 保存原始数据供后续分析

运维人员只需在运维端响应和完成工单，故障检测和工单创建完全自动化。
