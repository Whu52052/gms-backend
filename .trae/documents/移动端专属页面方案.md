# GMS 移动端专属页面方案

## Context（背景）

当前 GMS 系统的 index.html 是为桌面端设计的（侧边栏 240px + 主内容区），在 Android APK 的 WebView 中加载时，即使注入 CSS override 仍然出现侧边栏不显示、布局错乱等问题。原因是 WebView 运行时改 viewport 不可靠、登录是 SPA 路由切换不触发 onPageFinished、CSS @media 断点判断复杂等。

**根本解决方案**：做一个移动端专属页面 mobile.html，彻底采用移动 App 的布局范式（底部 Tab Bar + 卡片式列表 + 全屏表单），不再复用桌面端代码，与桌面端完全隔离互不影响。复用现有后端 API，无需改动后端。

## 设计目标

1. **移动 App 体验**：底部 5 Tab 导航，单手操作友好，符合微信/支付宝的使用习惯
2. **复用后端**：所有 API 不变，仅前端重写，零后端改动
3. **完整功能**：覆盖运维端所有 18 个功能模块
4. **UI 美观**：渐变色头部、卡片式布局、流畅过渡动画（符合用户 UI 偏好）
5. **独立部署**：mobile.html 独立文件，APK 默认加载此页面

## 实现步骤

### Step 1：创建 mobile.html 骨架
- 5 个 Tab 的主容器 + Header + Tab Bar
- 登录页（独立全屏，与主界面切换）
- 各 Tab 内容容器（默认隐藏，切换显示）
- 复用 css/style.css 的 CSS 变量（颜色/字体）保证视觉一致

### Step 2：创建 css/mobile.css
- 底部 Tab Bar 固定定位（高 56px + safe-area-inset-bottom）
- 卡片式列表样式（圆角、阴影、点击态）
- 渐变色 Header（按角色变色：管理员紫、运维绿、用户蓝）
- 表单组件（大输入框、大按钮，无解释性文字 — 符合用户偏好）
- 全屏模态层（工单详情、提交工单等）
- 加载态/空态/错误态样式

### Step 3：创建 js/mobile.js 核心逻辑
按功能分模块（同一文件内，对象式组织）：

```javascript
const MobileApp = {
  // ===== 基础 =====
  init(),                    // 启动：检查 cookie → 显示登录 or 主界面
  switchTab(tab),            // 切换底部 Tab
  _showLogin(),              // 显示登录页
  doLogin(),                 // 登录
  doLogout(),                // 退出

  // ===== 首页 =====
  renderDashboard(),         // 统计卡片 + 快捷入口
  _renderStatCard(),         // 单个统计卡片
  _renderQuickActions(),     // 6 宫格快捷入口

  // ===== 设备 =====
  renderInventory(type),     // 库存列表（手套/灵巧手/夹爪）
  renderMachines(),          // 机器列表
  _renderDeviceCard(),       // 设备卡片

  // ===== 工单 =====
  renderTechSupport(),       // 工单列表
  showTicketDetail(id),     // 工单详情（全屏模态）
  showNewTicketForm(),       // 提交工单表单
  submitTicket(),            // 提交工单

  // ===== 管理 =====
  renderAdminHome(),         // 宫格入口
  renderTransactions(),      // 流水
  renderAuditLog(),          // 审计
  renderUsers(),             // 用户管理
  renderSettings(),          // 设置
  // ... 其他子页面

  // ===== 我的 =====
  renderProfile(),           // 个人资料
  renderNotifications(),     // 通知
  renderMyActivity(),        // 操作记录
  showHelp(),                // 帮助
};
```

### Step 4：复用 js/api.js
- 不修改 api.js，直接 `<script src="js/api.js">` 引入
- API 类已包含 CSRF/cookie 鉴权、401 重定向、登录流程
- mobile.js 调用 `API.login()`、`API.getMachines()` 等方法

### Step 5：server.js 添加路由
- 在静态文件服务中确保 mobile.html、css/mobile.css、js/mobile.js 可访问
- 无需新 API，仅静态文件服务

### Step 6：修改 APK 加载 mobile.html
- 修改 MainActivity.java 的 `homeUrl` 为 `http://10.5.51.216:8765/mobile.html`
- 移除 onPageFinished 中的 CSS override 注入（不再需要）
- 移除 shortcuts.xml 中的快捷方式 URL 调整为 mobile.html

### Step 7：版本号升级
- app/build.gradle: versionCode 2→3, versionName "1.0.1"→"1.0.2"
- 重新构建签名 APK

## 关键设计细节

### 登录流程（复用现有修复）
- 调用 `API.login(username, password)` — 已包含 CSRF 令牌获取、独立 try-catch、session_expired 处理
- 登录成功后跳转主界面，失败显示错误（无爆破限制）
- Cookie 7 天有效，下次打开自动恢复登录

### 仪表盘卡片
- 4 个关键指标：在线机器、手套总数、损坏设备、今日操作
- 6 个快捷入口：手套库存、机器列表、提交工单、流水、SN 码、个人中心

### 工单提交表单（移动端友好）
- 全屏模态，大输入框，无解释性文字（符合用户偏好）
- 字段：设备编号（自动填充）、设备类型、故障现象、操作员、图片上传（可选）
- 复用 `POST /api/tech-support` 接口

### 设备列表（卡片式）
- 顶部分类 Tab：手套 / 灵巧手 / 夹爪 / 机器
- 卡片显示：编号、状态（彩色徽章）、关键信息、最后更新时间
- 点击卡片展开详情
