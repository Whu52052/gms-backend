一、SQLite 数据库优化
================================================================================

【技术】better-sqlite3 + SQLite PRAGMA 性能调优
【文件】server.js

【实现过程】
1. WAL 模式 (Write-Ahead Logging)
   - 命令: PRAGMA journal_mode = WAL
   - 原理: 写操作先写入 WAL 文件，再批量写入主数据库
   - 效果: 读写不互斥，多用户并发访问不阻塞

2. 内存映射 I/O (mmap)
   - 命令: PRAGMA mmap_size = 268435456 (256MB)
   - 原理: 将数据库文件映射到进程地址空间，减少 read/write 系统调用
   - 效果: 大文件随机读取速度提升 3-5 倍

3. 缓存大小
   - 命令: PRAGMA cache_size = -64000 (64MB)
   - 原理: SQLite 页面缓存，负数表示 KB 单位
   - 效果: 热数据常驻内存，减少磁盘 I/O

4. JSON 表达式索引
   - 命令: CREATE INDEX idx_tx_snCode ON transactions(json_extract(data, '$.snCode'))
   - 原理: SQLite 支持对 JSON 字段内的值建立索引
   - 效果: 按 SN 码查询从全表扫描变为索引查找，速度提升 100+ 倍

5. WAL 检查点
   - 命令: PRAGMA wal_checkpoint(PASSIVE) 每15分钟执行
   - 原理: 将 WAL 中的修改合并回主数据库，回收空间
   - 效果: 防止 WAL 文件无限增长

【使用示例】
  const db = new Database('data/gms.db');
  db.pragma('journal_mode = WAL');
  db.pragma('cache_size = -64000');
  db.pragma('mmap_size = 268435456');
  // 创建索引
  db.exec('CREATE INDEX IF NOT EXISTS idx_tx_snCode ON transactions(json_extract(data, "$.snCode"))');
  // 查询自动使用索引
  const rows = db.prepare('SELECT * FROM transactions WHERE json_extract(data, "$.snCode") = ?').all('SN001');

二、Canvas 图像压缩
================================================================================

【技术】HTML5 Canvas API + Image 对象
【文件】js/app.js → _compressImage(file)

【实现过程】
1. 读取文件
   - 使用 FileReader.readAsDataURL() 将文件转为 base64 Data URL
   - 非图片文件(PDF等)直接返回原始 Data URL，不压缩

2. 加载图像
   - 创建 Image 对象，设置 src 为 Data URL
   - 等待 onload 事件触发

3. 计算缩放比例
   - 目标: 长边不超过 1024px
   - const ratio = Math.min(1024 / img.width, 1024 / img.height)
   - 等比缩放，不变形

4. Canvas 绘制
   - 创建 canvas 元素，设置宽高为缩放后的尺寸
   - ctx.drawImage(img, 0, 0, newWidth, newHeight)
   - Canvas 内部使用双线性插值进行高质量缩放

5. 输出压缩
   - canvas.toDataURL('image/jpeg', 0.75)
   - 转为 JPEG 格式，质量 75%
   - 典型效果: 5MB PNG → 80KB JPEG (压缩比 60:1)

【完整代码】
  _compressImage(file) {
    return new Promise((resolve) => {
      if (!file.type.startsWith('image/')) {
        const reader = new FileReader();
        reader.onload = () => resolve(reader.result);
        reader.readAsDataURL(file);
        return;
      }
      const img = new Image();
      img.onload = () => {
        const maxDim = 1024;
        let w = img.width, h = img.height;
        if (w > maxDim || h > maxDim) {
          const ratio = Math.min(maxDim / w, maxDim / h);
          w = Math.round(w * ratio);
          h = Math.round(h * ratio);
        }
        const canvas = document.createElement('canvas');
        canvas.width = w; canvas.height = h;
        const ctx = canvas.getContext('2d');
        ctx.drawImage(img, 0, 0, w, h);
        resolve(canvas.toDataURL('image/jpeg', 0.75));
      };
      img.src = URL.createObjectURL(file);
    });
  }

三、Tesseract.js OCR 识别
================================================================================

【技术】Tesseract.js v5 (WebAssembly 版本)
【文件】index.html (CDN引入), js/app.js (_getOCRWorker, _onAttachmentChange)

【实现过程】
1. CDN 引入
   <script src="https://cdn.jsdelivr.net/npm/tesseract.js@5/dist/tesseract.min.js">
   - 浏览器端运行，无需服务器
   - WebAssembly 编译，性能接近原生

2. Worker 初始化
   - Tesseract.createWorker('eng') 创建英语识别 worker
   - 设置 PSM (Page Segmentation Mode) 为 7 (SINGLE_LINE)
   - 设置字符白名单: A-Za-z0-9-_. (排除标点干扰)
   - Worker 懒加载，首次用才初始化

3. 图像预处理管线
   a. 缩放: 短边至少 1200px (保证文字可辨)
   b. 灰度化: 加权公式 gray = 0.299R + 0.587G + 0.114B
   c. 对比度拉伸: 将像素值映射到 0-255 完整范围
   d. 自适应二值化: 积分图 + 局部均值阈值
      - 每个像素的阈值 = 周围窗口的均值 - 偏置(12)
      - 窗口大小 = min(宽,高) / 20
      - 积分图实现 O(1) 窗口求和
   e. 黑白反转: 如果黑色像素 > 55%，反转为白底黑字

4. 识别结果后处理
   - 字符纠正: O→0, l→1, S→5, Z→2, B→8
   - 正则匹配: 多模式匹配SN码格式
   - 自动填入输入框

【关键参数说明】
  - PSM_SINGLE_LINE (7): 告诉引擎图片是单行文字，精度最高
  - PSM_SPARSE_TEXT (11): 备选模式，用于单行识别失败时
  - tessedit_char_whitelist: 限制识别字符集，减少混淆

四、SSE 实时数据同步
================================================================================

【技术】Server-Sent Events (SSE)
【文件】server.js (broadcastSSE, /api/events), js/api.js (_listenSSE)

【实现过程】
1. 服务端 SSE 端点
   - GET /api/events
   - 设置响应头: Content-Type: text/event-stream, Cache-Control: no-cache
   - 将 res 对象加入 sseClients Set
   - 客户端断开时自动从 Set 移除

2. 广播函数
   function broadcastSSE(event, data) {
     const msg = `event: ${event}\ndata: ${JSON.stringify(data)}\n\n`;
     sseClients.forEach(res => { try { res.write(msg); } catch { sseClients.delete(res); } });
   }
   - 格式: event: 事件名\ndata: JSON数据\n\n
   - 遍历所有连接客户端，写入消息
   - 写入失败的客户端自动移除

3. 客户端监听
   const es = new EventSource('/api/events');
   es.addEventListener('transactions_updated', silentSync);
   es.addEventListener('machines_updated', silentSync);
   es.addEventListener('sn_registry_updated', silentSync);
   // ... 共 13 个事件类型

4. 防抖合并
   const silentSync = () => {
     if (this._refreshTimer) clearTimeout(this._refreshTimer);
     this._refreshTimer = setTimeout(async () => {
       if (API.online && !App._restoring) await Storage._syncFromServer();
     }, 500);
   };
   - 500ms 内的连续事件合并为一次同步
   - 恢复数据期间 (App._restoring=true) 阻止同步

5. 同步策略
   - _fullSyncFromServer: 全量替换 (登录、手动刷新时)
   - _syncFromServer: 增量更新 (SSE 事件触发时)
   - 每个数据类型独立 try/catch，一个失败不影响其他

【事件类型列表】
  inventory_updated, machines_updated, transactions_updated,
  settings_updated, equipment_config_updated, inventory_config_updated,
  users_updated, sn_registry_updated, audit_log_updated,
  ops_orders_updated, ops_customers_updated, ops_production_updated

3. 数据上限控制

     if (transactions.length > 10000) {
       transactions = transactions.slice(0, 10000);  // 保留最新 10000 条
     }
     localStorage.setItem(this.KEYS.TRANSACTIONS, JSON.stringify(transactions));
   }

4. 双模式同步
   - _fullSyncFromServer: 全量替换 (先清空已知键，再从服务器填充)
   - _syncFromServer: 独立同步 (每个数据类型独立 try/catch)

   - SN注册表: 每只手套的状态 (available/in_use/damaged/in_repair)
   - 两者独立维护:
     * 入库 → inv.quantity+1, 注册表新增 available
     * 上线 → inv.quantity-1, 注册表标记 in_use
     * 下线正常 → inv.quantity+1, 注册表标记 available
     * 下线损坏 → inv.quantity不变, 注册表标记 damaged
     * 维修完成 → inv.quantity+1, 注册表标记 available

七、自适应二值化图像预处理
================================================================================

【技术】积分图 + 局部均值阈值算法
【文件】js/app.js (_preprocessForOCR)

【实现过程】
1. 缩放放大
   - 短边至少 1200px (文字太小 OCR 无法识别)
   - ctx.imageSmoothingEnabled = true 保证平滑

2. 灰度化
   - 加权公式: gray = 0.299*R + 0.587*G + 0.114*B
   - 人眼对绿色最敏感，权重最高

3. 对比度拉伸
   - 找到最小和最大灰度值
   - 映射到 0-255: new = (old - min) / (max - min) * 255
   - 增强文字与背景的对比度

4. 积分图构建
   - 一维前缀和的二维扩展
   - integral[i][j] = 左上角所有像素之和
   - 公式: I(i,j) = gray(i,j) + I(i-1,j) + I(i,j-1) - I(i-1,j-1)

5. 局部均值自适应阈值
   - 窗口大小 = min(宽,高) / 30
   - 每个像素的局部均值 = (窗口内像素和) / (窗口面积)
   - 使用积分图 O(1) 计算窗口和
   - 阈值判断: gray > mean - bias ? 白 : 黑

6. 反转检测
   - 统计黑色像素百分比
   - 如果 > 55%，反转为白底黑字 (Tesseract 需要黑字白底)

八、RBAC 权限系统
================================================================================

【技术】基于角色的访问控制 (Role-Based Access Control)
【文件】server.js (requireAuth), js/app.js (_isPrivileged, _hasSNDeletePerm)

【实现过程】
1. 角色定义
   - superadmin: 超级管理员 (所有权限)
   - admin: 管理员 (可管理用户、配置)
   - user: 普通用户 (仅基本操作)

2. 服务端权限检查
   function requireAuth(req, res) {
     const auth = req.headers['authorization'];
     if (!auth || !auth.startsWith('Bearer ')) return null;
     return validateToken(auth.slice(7));
   }
   - 每个 API 请求验证 Bearer Token
   - 敏感操作检查 role 字段

3. 细粒度权限 (SN 删除权限)
   - 存储在 localStorage 用户对象的 permissions 字段
   - { permissions: { canDeleteSN: true/false } }
   - 超级管理员可以授予/撤销管理员的此权限
   - 检查: _hasSNDeletePerm() → role==='superadmin' || (admin && permissions.canDeleteSN)

4. 权限存储
   - 服务端 users 表存储基本角色
   - localStorage gms_users 存储细粒度权限
   - 渲染时合并两个来源的数据

九、防抖与搜索优化
================================================================================

【技术】setTimeout 防抖 (Debounce) + 键盘事件监听
【文件】js/app.js (applyFilter, globalSearch)

【实现过程】
1. 搜索输入改为回车触发
   - oninput → onkeydown="if(event.key==='Enter')App.applyFilter('search',this.value)"
   - 原因: 之前 oninput 每次输入都触发 renderTransactions 全页重渲染
   - renderTransactions 会销毁重建整个 DOM (包括搜索输入框)
   - 输入框被销毁 → 焦点丢失 → 只能打一个字母

2. 全局搜索优化
   globalSearch(query) {
     this.filters = {
       equipmentType: 'all', direction: 'all',
       dateFrom: '', dateTo: '',
       search: query,
       sortColumn: '', sortDirection: 'asc'
     };
     this.switchTab('transactions');
     setTimeout(() => {
       document.getElementById('filter-search').value = query;
     }, 100);
   }
   - 清空所有旧筛选条件
   - 切换到流水记录页面
   - 100ms 后恢复搜索框的值 (等 DOM 渲染完成)

3. 搜索范围扩展
   - 原来: 仅搜索 snCode, updatedBy, machineNumber, note
   - 现在: 增加设备类型中文标签、操作方向(入库/出库)、手型(左手/右手)

十、数据库自动迁移
================================================================================

【技术】SQLite ALTER TABLE + 错误容错
【文件】server.js (migrateDB)

【实现过程】
1. 问题
   - CREATE TABLE IF NOT EXISTS 只会创建新表，不修改已存在的表
   - 新增字段需要手动执行 ALTER TABLE ADD COLUMN

2. 迁移函数
   function migrateDB() {
     const migrations = [
       'ALTER TABLE sn_registry ADD COLUMN attachment TEXT',
       'ALTER TABLE sn_registry ADD COLUMN trackingNumber TEXT',
       'ALTER TABLE sn_registry ADD COLUMN shippedAt TEXT',
       'ALTER TABLE sn_registry ADD COLUMN repairedAt TEXT',
     ];
     migrations.forEach(sql => {
       try {
         db.prepare(sql).run();
         console.log('[MIGRATE] ' + sql);
       } catch (e) {
         // 列已存在，跳过
       }
     });
   }

3. 执行时机
   - initDB() 创建表
   - migrateDB() 追加缺失列
   - 每次服务器启动自动执行

4. 容错设计
   - 每个 ALTER TABLE 独立 try/catch
   - 一个失败不影响其他
   - 列已存在时静默跳过

十二、请求超时保护
================================================================================

【技术】setTimeout + AbortController + req.destroy()
【文件】server.js (parseBody), js/api.js (_fetchWithTimeout)

【实现过程】
1. 客户端请求超时
   _fetchWithTimeout(url, options, timeoutMs = 5000) {
     const controller = new AbortController();
     const timer = setTimeout(() => controller.abort(), timeoutMs);
     return fetch(url, { ...options, signal: controller.signal })
       .finally(() => clearTimeout(timer));
   }
   - AbortController 实现可取消的 fetch
   - 超时后 abort 信号触发 fetch 拒绝

2. 服务端请求体超时
   function parseBody(req) {
     return new Promise((resolve) => {
       const timer = setTimeout(() => {
         req.destroy();  // 30秒超时强制断开
         resolve({});
       }, 30000);
       req.on('data', c => { /* 收集数据块 */ });
       req.on('end', () => {
         clearTimeout(timer);
         resolve(JSON.parse(...));
       });
       req.on('error', () => {
         clearTimeout(timer);
         resolve({});
       });
     });
   }

3. 请求体大小限制
   const MAX = 50 * 1024 * 1024; // 50MB
   if (size > MAX) { req.destroy(); resolve({}); }

4. 服务端响应超时
   server.timeout = 5 * 60 * 1000;    // 5 分钟请求超时
   server.keepAliveTimeout = 120 * 1000;  // 2 分钟 Keep-Alive

十三、优雅关闭与崩溃保护
================================================================================

【技术】process 事件监听 + 资源清理
【文件】server.js

【实现过程】
1. 未捕获异常保护
   process.on('uncaughtException', (err) => {
     console.error('[FATAL]', err.message);
     // 记录到 crash.log
     fs.appendFileSync('data/crash.log', ...);
     // 尝试优雅关闭
     gracefulShutdown('uncaughtException');
   });

   process.on('unhandledRejection', (reason) => {
     console.error('[FATAL]', reason);
     gracefulShutdown('unhandledRejection');
   });

2. 优雅关闭流程
   async function gracefulShutdown(signal) {
     if (shuttingDown) return;
     shuttingDown = true;
     // 1. 关闭所有 SSE 连接
     sseClients.forEach(res => { try { res.end(); } catch {} });
     sseClients.clear();
     // 2. WAL 检查点 (将 WAL 合并到主数据库)
     db.pragma('wal_checkpoint(TRUNCATE)');
     // 3. 关闭数据库连接
     db.close();
     // 4. 退出进程
     process.exit(0);
   }

3. 系统信号处理
   process.on('SIGTERM', () => gracefulShutdown('SIGTERM'));
   process.on('SIGINT', () => gracefulShutdown('SIGINT'));

4. 请求级异常隔离
   http.createServer(async (req, res) => {
     try {
       // ... 所有路由处理
     } catch (e) {
       console.error('[REQUEST ERROR]', req.url, e.message);
       sendJSON(res, { error: '服务器内部错误' }, 500);
     }
   });

5. 定期维护
   - 每 15 分钟: WAL 检查点 + 清理死 SSE 连接
   - 每 24 小时: 数据库自动备份 (保留 7 份)
   - 每 2 小时: 健康日志 (内存/SSE/数据库大小)
