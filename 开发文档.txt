【一、技术框架】

  后端: Node.js + better-sqlite3 (SQLite WAL模式)
  前端: 纯原生 JavaScript SPA (无框架依赖)
  通信: HTTP REST API + SSE (Server-Sent Events) 实时推送
  存储: 服务端 SQLite 数据库 + 客户端 localStorage 缓存
  图像: Canvas API 压缩 + Tesseract.js OCR 识别
  部署: Windows (.bat) / Linux (systemd/sh) 双平台支持

【二、全部功能列表】

  1. 系统总览 — 仪表盘卡片(全部/损坏/售后中手套、在线机器、今日操作)
               卡片拖拽排序、库存趋势图表、机器利用率
  2. 手套库存 — 左右手独立管理、出入库录入SN码和照片、批量操作
  3. 灵巧手库存 — 同手套库存
  4. 夹爪库存 — Pika库存管理
  5. 自定义库存 — 动态库存类型(支持左右手配置)
  6. 机器管理 — 机器卡片、上下线流程、逐只SN码损坏选择
  7. 流水记录 — 全局搜索(回车执行)、设备/方向/日期筛选、分页
  8. SN码管理 — 三区展示(使用中/闲置中/售后损坏)、照片上传/删除
                 OCR自动识别SN码、快速L/R入库、重复SN检测
  9. 售后管理 — 损坏库存→发货厂家(批量/快递单号)→维修完成(批量)
  10. 系统设置 — 仪表板配置、库存阈值、设备/库存类型配置
                 数据备份恢复、数据完整性检查、关于/版本历史
  11. 用户管理 — 添加/删除用户、角色管理、SN删除权限赋权
  12. 审计日志 — 中文操作类型显示

【四、使用的技术类型】

  - SQLite性能优化: WAL模式, mmap内存映射, 64MB缓存, JSON表达式索引
  - Canvas图像压缩: 缩放至1024px + JPEG 75%质量
  - Tesseract.js OCR: 浏览器端光学字符识别，PSM_SINGLE_LINE模式
  - SSE实时同步: 服务端广播 + 客户端事件监听 + 恢复期阻塞保护
  - localStorage离线缓存: 全量替换同步 + 增量合并双模式
  - HTML5 Drag & Drop: 仪表盘卡片拖拽排序
  - 自适应二值化: 积分图 + 局部均值阈值图像预处理
  - 权限系统: 基于角色的访问控制(RBAC) + 细粒度SN删除权限
  - 防抖(Debounce): 搜索输入300ms防抖
  - 数据库迁移: ALTER TABLE + migrateDB自动迁移
  - 数据库备份恢复: 24小时自动备份 + 手动恢复脚本
  - CSV/Excel导出: BOM UTF-8编码兼容中文Excel
  - 请求超时保护: parseBody 30秒超时

【五、如何使用】

  启动服务器:
    Windows: 双击 start-server.bat (自动重启，崩溃自恢复)
    Linux:   ./start-server.sh 或 sudo systemctl start glove-management

  数据恢复:
    Windows: 双击 restore-data.bat
    Linux:   ./restore-data.sh

  访问地址:
    本地: http://localhost:8765
    局域网: http://<IP>:8765

  默认账户:
    用户名: admin  密码: admin123  角色: 超级管理员

  基本流程:
    1. 库存类型配置 → 添加自定义库存类型
    2. 设备类型配置 → 配置设备消耗的库存物品
    3. 出入库 → 录入手套/灵巧手SN码和照片
    4. 机器管理 → 上线(必选SN码) / 下线(逐只选择损坏/正常/调用)
    5. 售后管理 → 损坏库存 → 批量发货厂家(填快递单号) → 批量维修完成
    6. SN码管理 → 三区展示(使用中/闲置中/售后) + 照片上传/删除 + 快速L/R入库
    7. 流水记录 → 回车搜索、筛选查看所有操作
    8. 系统设置 → 备份恢复、版本历史

  快速L/R入库格式:
    RWG1K01260321284 → R=右手, WG1K01260321284=SN码
    LWG1JA02260403004 → L=左手, WG1JA02260403004=SN码
    支持换行/空格批量输入，自动检测重复SN并跳过

  售后流程:
    机器下线选择"损坏" → SN进入损坏库存
    → 售后管理 → 批量发货给厂家(填快递单号) → SN进入售后中库存
    → 厂家修好寄回 → 批量维修完成 → SN回到空闲库存
